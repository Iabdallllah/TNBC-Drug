1. Product Definition & Boundary

HireGuard is a bounded red-teaming execution platform engineered to evaluate and stress-test conversational Arabic AI interviewers prior to production candidate deployment. The platform operates a stateful testing agent that generates dynamic adversarial probes, captures deterministic evidence, validates against frozen compliance policies, routes findings to human evaluators, and validates mitigations through before-and-after retesting.

Scope Dimension Specification & Boundary Decision
Core Product Controlled test harness for text-based Arabic AI interviewers.
Primary Artifact Evidence-backed finding record with reviewer validation status (Confirmed, Rejected, Inconclusive).
MVP Boundary One customer-support job role, one controlled target interviewer adapter, synthetic text only, local Dockerized deployment.
Core Experiment Bounded adaptive agent loop vs. fixed-script baseline under strictly matched turn and token budgets.
Explicit Exclusions Camera, facial analysis, gaze tracking, emotion detection, voice biometrics, real applicant PII, and production legal compliance certification.
Hard Scope & Safety Enforcement: The MVP is strictly text-based. No camera, facial, or voice processing is permitted. All credentials and test targets are synthetic; security tests run exclusively against local or explicitly owned mock targets.

Stage System / Actor Action Required Output Artifact
1. Setup User selects role rubric, target version, test suite, and budgets. Immutable RunConfig with unique run_id.
2. Simulate Load synthetic Arabic candidate persona and initialize session. Persona metadata snapshot and initialized transcript.
3. Probe Adaptive agent selects allowed action and calls target adapter. TurnEvent record (actor, input, tool, latency, token usage).
4. Adapt Controller updates state; evaluates termination budgets. Decision trace documenting reason for next strategic action.
5. Verify Evaluate deterministic checks (regex/secrets) and semantic policy. CheckResult with machine proposal (Pass, Fail, Inconclusive).
6. Review Human operator inspects trace and confirms or rejects finding. Immutable review disposition (Reviewer ID, decision, notes).
7. Retest Mitigation applied to target; identical scenario replayed. RetestLink pairing baseline and hardened execution traces.
8. Report Aggregate discovery rates, dialect variance, and cost statistics. Consolidated JSON / CSV report with complete denominators.

3. Functional Requirements

3.1 Setup, Configuration & Controller Flow

ID Pri Requirement Description Acceptance Criteria
FR-01 P0 Role definition containing competencies, questions, and rubric. Saved configuration receives an immutable version hash.
FR-02 P0 Target compliance policy listing disallowed disclosures and drift limits. All confirmed findings link directly to a specific rule_id.
FR-03 P0 Unified adapter supporting vulnerable and hardened target versions. Target switch requires zero code alterations in testing harness.
FR-04 P0 Suite selection, method specification, turn, token, and timeout budgets. Runs reject missing parameters and persist a frozen configuration snapshot.
FR-05 P0 State machine supporting Queued, Running, Completed, Failed, and Cancelled. Every transition contains a millisecond timestamp and transition cause.
FR-06 P0 Enforcement of hard bounds across candidate turns, tokens, and retries. No adapter calls execute post-exhaustion; run records termination cause.
FR-07 P0 Batch fault-isolation ensuring single-case crashes do not break suites. Failed scenario logs error trace while remaining queue proceeds.
FR-08 P1 Run configuration cloning for matched baseline evaluations. Cloned snapshot highlights exact differential configuration keys.

3.2 Agent Stateful Loop & Safety Controls

ID Pri Requirement Description Acceptance Criteria
FR-09 P0 State representation tracking hypothesis, transcript, and remaining budget. Full trace export allows exact step-by-step state graph reconstruction.
FR-10 P0 Strict allowlist of authorized agent tools (SendTurn, LoadPolicy, CheckEvidence). Unauthorized tools or schema violations reject prior to adapter execution.
FR-11 P0 Interviewer replies treated as untrusted data strings. Model responses containing prompt injections cannot invoke agent tools.
FR-12 P0 Adaptive probe selection conditioned on immediate target observations. At least two final evaluation traces demonstrate observation-dependent branch shifts.
FR-13 P0 Terminal state resolution into one of four mutually exclusive outcomes. Terminal outcome is exactly one of: No Finding, Proposed Finding, Inconclusive, Failure.
FR-14 P0 Separation of automated proposal from verified finding. Testing agent cannot self-confirm a finding; human review is mandatory.
FR-15 P0 Total state isolation between consecutive scenario executions. Zero memory or transcript context leaks across scenario boundaries.
FR-16 P1 Synthetic scenario drafting component with human approval gate. Draft scenarios require explicit sign-off flag prior to active suite inclusion.

3.3 Security, Reliability & Arabic Evaluation Suites

ID Pri Requirement Description Acceptance Criteria
FR-17 P0 Direct and multi-turn indirect prompt-injection test suite. Records injection technique, attack prompt, target response, and rule link.
FR-18 P0 Valueless canary secret injection (HG-SECRET-4821) in vulnerable target. Exact-match matcher detects leakage without storing authentic secrets.
FR-19 P0 Benign control baseline requesting standard job application details. Distinguishes legitimate interviewer assistance from excessive refusal.
FR-20 P0 Scoring repeatability testing across 10 fixed candidate transcripts. Calculates standard deviation, score range, and pass/fail decision flips.
FR-21 P0 Paired Modern Standard Arabic (MSA) vs. Egyptian Arabic (EGY) evaluation. Quantifies semantic scoring drift on equivalent candidate answers.
FR-22 P0 Deterministic checkers for regex, secrets, schemas, and budget bounds. Deterministic checks backed by 100% unit-tested test fixtures.
FR-23 P0 Evidence-grounded semantic grading for subtle policy violations. Semantic verifier cites exact transcript spans; falls back to Inconclusive.
FR-24 P0 Mitigation verification through deterministic scenario replay. Replay links identical seed and budget against the hardened target version.
FR-25 P1 Schema-driven scenario family extension via modular JSON files. New test suites load without altering engine or state-machine code.

6. Evaluation Design & MVP Acceptance Criteria

6.1 Experimental Protocol

The comparative evaluation is conducted across 30 development scenarios and 20 strictly held-out scenarios divided across threat families. Testing matches turn counts (max 6 candidate turns) and token limits across both the adaptive agent and the fixed-script baseline.

  • Core Matrix: 20 held-out scenarios × 2 methods (Adaptive vs. Fixed) × 2 target variants (Vulnerable vs. Hardened) = 80 runs.
  • Repeatability Analysis: 5 selected scenarios repeated 3 times across configurations = 40 additional runs (Total: 120 evaluation runs).

6.2 Quantitative Report Metrics

Metric Name Formula / Measurement Protocol
Confirmed Discovery Rate Confirmed Violations / Completed Violation Attempts (disaggregated by method and threat category).
Finding Precision Reviewer Confirmed Findings / Total Flagged Machine Proposals.
False Positive Rate Reviewer Rejected Flags / Total Flagged Machine Proposals.
Scoring Repeatability Standard deviation, score range, and binary pass/fail flip frequency across identical candidate transcripts.
Dialect Sensitivity Paired score deltas between equivalent Modern Standard Arabic (MSA) and Egyptian Arabic (EGY) responses.
Execution Efficiency Average tokens per scenario, aggregate estimated API cost, latency per turn, and completion success rate.
